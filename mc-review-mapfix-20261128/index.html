📝 本批建模经验总结（14 条）

这 25 辆新建／改编组里总结出来的要点，下次建模、返工直接对照：

  1. 搜图须同时试形式名与车号：nankai-cable 初查按车号（N11/N21）搜不到判无图，实际文件用形式名（N10・20形）。H 组纠正后 G 组建成。
  2. 简报给的图纸也可能错：坂本ケーブル简报给的 keihan_600_sakamotocable 是京阪 600 形电车主题涂装，不是缆车；真图是 hieizan_en/huku。建前必须开 PDF 核实内容，不能只信文件名。
  3. 候选图可能是错车：大井川 DD20 的 jnr_dd20_1/2 是 1963 年国铁试作机，不是大井川 1982–86 年製 DD201–DD206；开 PDF 看标题与正文才能定。223-5500 同理：223-5000 是 4 辆マリンライナー用车，不能冒充 5500。
  4. 缆车是 2 辆交走式、每辆各有身份：筑波（もみじ/わかば）、箱根（Ke11/Ke12）、坂本（縁/福）、南海（N11/N12）——一车一 commit 亦可，但同一 slug 下两车各一 commit 更贴合“每辆一 commit”。
  5. 裙板白围裙新法：skirt_texture (v4) 只清贴图左右 2 列 alpha，端面下段被黑带/灰腿围住的白纸仍不透明；修法为裙板贴图过 rgba_from_luma（白纸→透明）。共享 builder v4 本身未改，待 skill 维护方跟进。
  6. 新 builder 端盖键一律用 front/frontf/end/endf：非标准键（frontA/frontB、inner）落到默认分支，u 被定死成单列拉伸，司机面风挡全失（南海初版一端纯红、一端白噪点）。
  7. 端面贴图边缘约 9px 白纸会在斜视角成细白竖条（胶耳类）：逐行延展邻接面色清掉（fix_face_edges.py）。
  8. 前脸/贯通端白胶耳新法 clean_flaps：逐行取最长连续非白行（前脸本身），用行中部 50% 中值色填充行外，行两端偏离中值 >60 的像素各修掉 ≤15 px（去黑条与抗锯齿亮边）。
  9. Tc 侧墙漏画司机门时用同型 Mc 侧墙（同车体、同门布局），并核对现役同型模型是否同一修法（800番台已验证）；副作用（Mc 厕所小窗带入 Tc）须披露。
  10. 净片两侧墙是同一张画的不同朝向：SIDE_R 经 CW 旋转 + 镜像后与 SIDE_L 平均绝对差仅 2.96，两侧各用其一可使司机门在两面都在司机端；无重绘时不用 mirror_side。
  11. 中间车重组法（toei-5500 法）：图纸无中间车净片时，侧墙 = Mc 侧墙司机门区用同一侧墙窗片整高克隆覆盖；车顶用 Tc 车顶（无弓）或 Mc 车顶移植弓；两端贯通端；车底按车取（サハ取 Tc UNDER、モハ取 Mc UNDER）。弓位须按图纸实测 + 实车照片定案，不能只按“镜像对称”推测（E131-800 调查“1/3”已被推翻，实测为 Tc 侧端距端约 1.2 m）。
  12. 改编组先核实源模型：tobu-10000 源模型只有 1 辆司机室车，2 辆编组重组需要的第二辆司机室车不存在，镜像复用属虚构——BLOCKED。tobu-8000 源模型 GLB 导出方向与他组相反，常规顺序两端司机面朝内，须倒置顺序 [car6,car3,car2,car1]。西武2000 PLAIN 斜视角重叠是源模型坐标系问题，SITE 图正常——审核须以 SITE 图为准。
  13. R3 证据与 should_be 可能自相矛盾：tobu-500 的 R3 证据写 3 辆、should_be 写 6 辆；核实三列夜行现行均为 3 辆编组后按现实建 3 辆版，names 键改指待裁决。建模须以实车为准，不唯清单是从。
  14. 多车共网渲染：render_net.py 按 NETS 枚举车辆，多车共用网时只渲 2 辆；须按 CARS 枚举（I 组 render_seibu.py 已修，后续组可复用）。
